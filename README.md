# GUOFLIX 线路仓库（guoflix-routes）

这个仓库只放一份播放线路配置，供 GUOFLIX 电视端（0.13.4 及以上）读取。
电视端每 6 小时自动检查一次，也可以在「设置 → 刷新线路配置」手动刷新。
**换源只需要改这个 JSON 并提高 `revision`，不需要重新安装 APK。**

## 文件

- `playback-routes.json` — 线路配置本体（schema 2）

## 怎么改（换源流程）

1. 编辑 `playback-routes.json`。
2. 把 `revision` 改大（例如 `2026102102` → `2026102103`）。电视端只会接受比本机更新的版本。
3. 提交。
4. 电视上「设置 → 刷新线路配置」，看到 `R2026102103` 即生效。

## 结构

```json
{
  "format": "guoflix.playback-routes",
  "schema": 2,
  "revision": 2026102102,
  "routes": [ { "...线路1..." : "" }, { "...线路2..." : "" } ]
}
```

每条线路的字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识，`[a-z0-9_-]{1,24}`，用于失败冷却与排错 |
| `label` | 电视上显示的名字，例如「高清线路」 |
| `kind` | `api`（JSON 取流接口）或 `web`（网页取直链） |
| `host` | 只允许公开 https 域名，不接受 IP、localhost、`.local`/`.internal` |
| `path` | 以 `/` 开头的路径，可用占位符 |
| `query` | 查询参数，键 `[a-z0-9_]`，值不得超过 200 字符 |
| `headers` | 请求头，键 `[a-z0-9-]`，禁止 `host`/`content-length` 等 |
| `body` | 仅 `api` 线路需要，必须是 JSON，可用占位符 |
| `roles` | `hd`（高清线路）、`alt`（旧高清线路）、`web`（官网兼容线路） |

可用占位符：`{vid}` 单集 id、`{series}` 剧集 id、`{ts}` 秒级时间戳、`{rticket}` 毫秒时间戳。
其他占位符、以及任何 `://` 链接都会被电视端直接拒绝——配置里不能塞回调地址或跳转地址。

`roles` 决定它在电视「播放线路」菜单里的位置：

- `hd` → 「高清线路」
- `alt` → 「旧高清线路」
- `web` → 「官网兼容线路」
- 「自动切换」按文件里的顺序依次尝试，第一个成功即用。

## 当前这份配置在做什么

1. `multi`（hd）：`/novel/player/multi_video_model/v1/`，游客参数、无需签名，返回 360/480/540/720/1080 五档。
2. `single`（alt）：`/novel/player/video_model/v1/`，2026-10-21 起该接口稳定返回空响应，留作备用位。
3. `web`（web）：官网播放页内嵌直链，实测只有 360p，作为最后兜底。

## 安全边界

电视端不会执行这个文件里的任何代码，也不会跟随配置里给出的 URL 去访问；它只按白名单字段发一个固定形状的请求。
域名必须是公开域名，配置大小上限 16 KB，请求体上限 4 KB。
单条线路连续失败后会进入 5 分钟冷却，直接跳到下一条，避免每次起播都卡在死线路上。

## 若接口彻底变形

如果上游改成必须签名的协议（`x-gorgon` 一族），这份 JSON 就表达不了了，
需要发布新的 APK 来改客户端取流逻辑；只要仍是「某个 host + path + query + body 返回 JSON」，
就仍然只改这里即可。
